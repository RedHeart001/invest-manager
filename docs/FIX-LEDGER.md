## 验证门槛（权威现值）

> 其他文件只引用本节，不复述验收计数。旧套件数、断言数和本地回执是写下时的历史读数，不是永久目标。
> 本地 `*.out` / `*.log` 多数被 gitignore，新克隆没有；文件名不是跨机凭证，关键结论须落正文或长期价值报告。

### 通用证据规则

- 每套独立核对 `exit=0`；wrapper 的“断言 N/N”是实跑数，是否通过看 exit code。
- 失败先区分外部源态、仪器错误和代码回归；不得为凑绿重复购买上游或 LLM 额度。
- 测试失败最多重试 3 次（[PLAN.md](PLAN.md) R9）。
- 开发期间不在 dev server 运行时执行 `npm run build`。
- 修失败负缓存、限流计数、熔断计数、复查窗口等必须附 C34 反向验证；触及取数/限流的批次须跑相应闸2/闸4，并保留能精确翻红的负向样本。

### 闸1：离线门禁

```bash
node scripts/gate.mjs --offline
```

覆盖 `npx tsc --noEmit`、`npx vitest run`、DS 离线逐套、docs 闸与 selftest。通过条件：tsc 无错误、Vitest 无失败、DS 离线逐套通过、docs `NEW=0 / KNOWN=0/0`、断链 0、selftest PASS。

DS 套件必须按真实文件名逐套运行：

```bash
PYTHONPATH=. .venv/Scripts/python tests/test_<真实文件名>.py
```

禁止 `tests/test_*.py` 通配，避免卷入实网套件。p0/p1/p6 属付费或实网名单，由离线闸摘出；p6 不得再被当成离线套件。

### 闸2：跨服务契约

碰 `DS_RESPONSE_FILES` 任一文件，动工前必须二选一：

1. 同轮执行 `test-script/window_contract.py --live --write` 重采；
2. 登记 `KNOWN_STALE_SNAPSHOTS`。

不选会红，dirty 改动同样视为“现在”。重采后必须移除已被新证据覆盖的 `KNOWN_STALE`。

`/products` 属 `EXPENSIVE`，默认计划排除，只有显式 `--only /products` 才执行；单条探测预算为 600s，不得退回旧 180s。当前契约重采未验，闸1全绿或 KNOWN_STALE 在册不能替代。

### 闸3：DS 实网 p0 / p1

- 需 uvicorn 在跑且外部源可用；p0/p1 逐套核对 exit。
- 主源态、备源态均由回执字面事后判定；重启 DS 不是主源态保证，两档都可能是合法验收形态。
- 输出重定向到文件并单独记录 exit；不得经管道后用 `$?` 充当套件 exit。
- us 主源格按自然观察处理，不为补格自动重试。

### 闸4：完整七套集成

```bash
node web/scripts/verify-all.mjs
```

完整通过须同时满足：

- 七套逐套 `exit=0`；
- 末行 `ALL DONE`；
- 断言缺口 0；
- 无“套件非零退出”或 `GATE FAILED`；
- `PLANNED` 可登记多个合法形态，实跑不在任一档才计缺口。

运行边界：

- 跑集成期间不得编辑 `web/**`，包括 `web/scripts/`；见瞬态 500 先复探 3 次。
- p3 会真跑 pipeline 并写库；p4/p5/p6 均可能涉及真实 LLM，排窗口和授权时必须计入。
- `verify-all` 强制 localhost 且会写库，**不能直接对开发实例运行**；使用 CR10-31 的隔离启动器。
- 当前完整七套仍未验，不得用历史 `ALL DONE`、P0 冷启动或 fixture 补齐。

### 闸5：改后探针与装载

- dev uvicorn 不加 `--reload`。
- 凡以“实测”为证据的改动，必须有改后探针，证明新行为已在当前运行进程生效。
- 重启后确认监听 PID 已变化，且新日志无 `10048`；旧进程仍健康不能证明新码装载。
- 旧“现值”绑定旧进程；进程消失后装载结论失效，必须重读。
- 改 route 后第一次请求可能由旧 handler 或首编译承担；首请求不算改后探针，必须复探。
- 期待自然调度证据前先确认进程在场。任务有 `misfire_grace_time=1800`：短睡可迟到补跑，超过后可能丢腿，不能沿用“绝不补跑”的旧口径。
