## 2. `sourceUrls` 形状 —— 证明"标题在后端被丢弃"且"cls 批次无链接"

板块异动：林业领涨（8 | n_urls= 0 | []

- 前 3 行均属 `cls` 批次，`sourceUrls` 长度 **0**。根因是 `_cls_telegraph` 写死 `"url": ""`（`pipeline.py:146`），而 `_topic_urls` 的 `if n.get("url")` 把空串过滤掉（`:553`）。

## 5. eastmoney 令牌桶在单次 pipeline 内的争抢点 —— OPT-2 的量化代价

```bash
grep -n "_EM.acquire" data-service/app/hotspot/pipeline.py
# 159:    if not _EM.acquire(timeout=15):     ← _em_global_news（东财快讯）
# 255:    if _EM.acquire(timeout=15):         ← _board_names（板块名单）
# 498:    if _EM.acquire(timeout=15):         ← map_board_products（成分映射，每 topic×board 各一次）
sed -n '21,30p' data-service/app/utils/limiter.py
# min_interval 5.0 / burst 2 / rate_per_min 12 / failure_threshold 2 / cooldown_base 180.0 / cooldown_max 900.0
```

- `map_board_products` 按 `t.get("boards", [])[:2]` 调用，`TOPIC_LIMIT` 内最多 **5 topic × 2 board = 10 次 acquire**，最小间隔 5s → 单这一段就有约 50s 的下限。
- 拿不到令牌的后果：转新浪备源 → 生成 `pipeline.py:455` 的「新浪板块名称未匹配」→ **正是 CR8-1 要从界面摘掉的 ③**。
- 今日 9 行里 `newsSource` 只有 `cls` 与 `tavily`，**东财快讯一次都没被调用**（它在 `fetch_news` 的循环里排在 cls 之后，`:203`）→ 它作为主源的稳态负载零实测数据。

## 6. env 键位核查（只测空/非空，未打印任何值）

```bash
for f in .env web/.env; do for k in LLM_BASE_URL LLM_API_KEY LLM_MODEL TAVILY_API_KEY INGEST_TOKEN; do ... done; done
```

| 键 | 根 `.env` | `web/.env` |
|---|---|---|
| `LLM_BASE_URL` | 空 | 未设 |
| `LLM_API_KEY` | 已填 | 已填 |
| `LLM_MODEL` | 已填（`deepseek-flash`） | 已填（同值） |
| `TAVILY_API_KEY` | 已填 | 已填 |
| `INGEST_TOKEN` | 已填 | **未设** |

- **两侧都有模型名推断 base_url**：`web/lib/llm.ts:50-56` 与 `data-service/app/hotspot/llm_client.py:26-33` 逻辑一致（含 `deepseek` → `https://api.deepseek.com`）。所以"`LLM_BASE_URL` 为空"**不是** ② 退化的原因。
- `data-service/app/config.py:6,57` 把 `TAVILY_API_KEY` 别名为 `SEARCH_API_KEY`；`pipeline.py:31` 的 `load_env()` 除自身目录外还读 `../web/.env`。
- `web/.env` 没有 `INGEST_TOKEN` 不影响本地落库：`web/app/api/hotspots/ingest/route.ts:9-12` 与 `api/research/ingest/route.ts:10` 都是"未配置即跳过校验"。
- 结合第 1 节（同进程 17:06 成功、17:14 失败）：② 的"LLM 未配置或不可用"当日实况是**瞬时网络失败**，不是配置缺失。
