## 逐项做法

### CR10-23：部分失败不推进完成账本

- `web/lib/refresh-progress.ts`：`lastCompleted[type]` 只在 `updated > 0 && failedBatches === 0 && !skipped` 时写入。
- 部分结果仍保留在 `done` 供归因，但不计入当日完成，避免下一次普通触发被幂等闸门挡住。
- 回归：部分失败不盖章；已有完成时刻不被后续部分失败轮重新盖章。

### CR10-24：恢复源 schema 校验与统一回滚

- `data-service/scripts/backup_db.py`：恢复源必须含 `Product` 表及 `id/type/code/name` 核心列；不要求有数据行，冷启动空库可恢复。
- 主库、`-wal`、`-shm` 的改名与 backup API 写回进入同一异常边界；`write_started` 之前失败只还原已挪走文件，不误删原库。
- 回滚按逆序还原，并清理写回阶段可能产生的目标库 sidecar。
- 回归：`data-service/tests/test_backup_db.py` 覆盖无关 schema 拒绝、冷启动恢复、主库／WAL／SHM 三个改名失败点、真实 `backup()` 写回失败；全部使用临时合成库。

### CR10-25：研报拒绝结构化原因

- `data-service/app/research/tasks.py`：`reason` 三态 `running`／`today_done`／`capacity`；保留 `todayDone` 兼容。
- `web/lib/research.ts`：`capacity` 直接返回 rejected，不登记 watcher；只有真实运行任务（含无结构化 reason 的旧响应）登记 watcher。
- 回归：Web `research.test.ts` 覆盖 HTTP 409／200 两种容量满、同标的 running、旧兼容分支；新增 `tests/test_cr10_25_research_rejections.py` 5 枚。

### CR10-26：空价保留最后有效值

- `web/lib/realtime.ts`：新增 `hasValidPrice()`；`mergeTick()` 在空价时保留上一份 `price`／`observedAt`／`intraday`／可见状态。
- `web/app/product/[type]/[code]/RealtimeStrip.tsx`：只有有限数值报价刷新 `lastOk` 并清零失败计数；空价计入失败计数。
- 回归：有效价→空价→恢复；首次空价不伪造旧值。

### CR10-27：反证测试已落，实现未动

- 新增 `web/lib/kline-tail-refresh.test.ts`：缓存末日等于请求末日时仍须回源、从缓存末日起、只更新尾部行且总行数不增；30 分钟窗口内第二次不回源。
- 11-12 23:20 实测：该文件 1 失败／1 通过。失败点为旧实现 `kline.ts:344` 的 `maxCached < end` 门槛，`dsGet` 零调用。
- 生产缺口三处：`web/lib/kline.ts:344` 的尾部门槛、`:351` 的 `maxCached + 1` 起点、`:217` 只有 `INSERT OR IGNORE` 无尾部更新路径。
