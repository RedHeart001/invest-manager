# CR10-22：损坏源备份失败产物残留修复（2026-11-12）

## 发现与根因

- 完整离线门禁首跑时，`test_backup_db.py` 两条 D1 断言失败：损坏源备份返回空字符串后，输出目录仍多出一个 `dev-*.db`。回执＝`data-service/runtime/gate1-17-1112-1919.out`。
- 单独复跑该套件与第二次完整门禁均通过，说明自然计时会让结果跨秒或同秒而变化，不能把单次通过当作缺陷不存在。
- 根因位于 `data-service/scripts/backup_db.py`：`src.backup(dst)` 抛出 `sqlite3.DatabaseError` 后，在 `try` 内直接 `return ""`，跳过后面的 `os.remove(dest)`。文件名精度为秒；与上一份备份同秒时会覆盖旧路径而掩盖残留，跨秒时才暴露为额外文件。

## 可控复现与修复

- 在临时目录构造合法库与非 SQLite 文件，将两次 `now()` 固定为相邻两秒。修复前第二次调用返回 `""`，目录留下两个 `.db`，其中失败产物为 0 字节。
- 修复仅改失败控制流：记录源读取异常，关闭连接后统一进入无效产物清理；成功路径与恢复逻辑不改。
- `data-service/tests/test_backup_db.py` 使用 mock 固定相邻时间戳，使失败产物残留成为确定性判据，不再依赖真实时钟跨秒。
- 生产调用方仅为备份调度链 `backup_scheduler.py → backup()`；本项不涉及 `DS_RESPONSE_FILES`，不触发闸2重采。
