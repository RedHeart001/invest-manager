## 2. 目标与非目标

**目标**：① 海外源（CoinGecko、Tavily、yfinance/OpenBB、HKEX）显式使用本机代理；② 东财、新浪、腾讯及容器间调用始终直连；③ A 股东财主源失败时不用新浪整类替换；④ 失败类型每日最多自动补试一次，成功类型不重复出网；⑤ 页面优先最新，失败时展示最近成功快照并明确标注；⑥ 热点恢复真实 LLM 结构化，Tavily 只作三源之一；⑦ 用自然调度验证。

**非目标**：不承诺彻底解决运营商、CDN 或 TLS 间歇故障；不全局套代理；不因当前探针成功就宣称凌晨故障消失；不改 CoinGecko／HKEX／东财现有分页和重试算法；不放宽 70% 缩水闸、空载荷保护、完整性检查或热点 `degraded` 判定；不把新浪 A 股／港股当等价完整名单；不无限重试、不增加并发、不绕开源族限速；不处理 `r_` 长期配额、全量 4,596 只港股刷新和美股盘中可选补证；不删除或改写 11-26、11-27 原始失败现场。

## 3. 原则与状态模型

| 层面 | 原则 |
|---|---|
| 获取 | 主源、等价 host、等价备源、正确网络路径和有限补试，尽最大努力拿到新数据 |
| 入库 | 只有完整、有效、口径兼容的候选才能替换正式数据 |
| 展示 | 优先最新；失败时展示最近成功数据，并明确标注年龄和状态 |

“数据库保留旧数据”与“页面展示旧数据”不是同一件事：保留是恢复和回退的基础；把旧数据无提示地当成最新才是缺陷；当日新产出但质量降级不等于旧数据，必须单独标 `degraded`。

| 状态 | 含义 | 页面行为 |
|---|---|---|
| `fresh` | 最新获取成功且满足新鲜度 | 正常展示，显示实际数据时间 |
| `degraded` | 最新数据已取得，但来源或结构化降级 | 展示当日数据，明确标注降级 |
| `stale` | 最新获取失败，展示最近成功快照 | 展示旧数据，醒目标注历史状态、数据时间和最近成功时间 |
| `unavailable` | 从未取得有效数据 | 显示“暂无数据／获取失败”，不虚构 |

`stale` 与 `degraded` 必须分开：旧数据不一定降级，新数据也可能降级。每类视图至少能回答：`status`、`dataAt`、`lastAttemptAt`、`lastSuccessAt`、`source`、`degraded`、`error`（脱敏）。不要求一次性给所有 DS 响应加同样字段，可在 Web 读侧组合同步状态、`Product.updatedAt`、`Product.snapshotAt` 和行情时间戳。

| 源族 | 出网策略 |

| `web`、`data-service`、localhost | 永远直连 |

建议新增 `data-service/app/utils/http.py`，只提供 `overseas_proxies()`（未配置返回 `None`）和 `direct_session()`（`trust_env=False`、空 `proxies`）。第一轮不设计通用重试器、自动代理故障切换或连接池框架。

改造点：`crypto_provider.py` 保留两次请求、20s 超时和 300s 失败冷却，只收敛代理读取；`openbb_provider.py` 复用同一函数，不改 yfinance 批量与降级；`hotspot/pipeline.py` 的 Tavily 复用同一函数，保留两条查询、25s 超时、合并去重和失败降级；`hk_provider.py` 的 HKEX 用海外 Session，东财用直连 Session，保持 40s 单请求、120s 看门狗和 XLSX 校验；`akshare_provider.py` 的 `_em_get` 用直连 Session，不改 host 顺序、两轮降级和源族限速。

根 `.env` 配置：

```dotenv

HTTPS_PROXY=http://host.docker.internal:7897
```

暂不做“直连失败后自动换代理重试”：会让失败请求量和耗时翻倍、可能绕开源族限速、当前样本不足以证明收益，也容易掩盖哪条路径恢复。先让海外源按配置走显式代理，并保留错误类型和路径证据。

## 7. W2：A 股新浪降级改为 fail-closed

东财主源失败时：仍可采集新浪作诊断；不声明为可发布完整候选；明确返回采集不完整及主备错误；Web 拒绝写入并保留现有 `Product`；`stock` 记入本轮降级失败，不伪装成同步成功。

现状：`akshare_provider.py` 的 `_list_stocks()` 在东财成功时返回 `products, {"source": "akshare"}`；失败时调用 `ak.stock_zh_a_spot`，返回 `source="sina-a-share-spot"`、`degraded=True` 的候选，Web 目前会接受并整类替换。`list_products_with_meta()` 会把 `(items, meta)` 合并，`/products` 再展开到响应顶层，因此可复用现有元数据契约。

建议返回：

```json
{
  "products": [],
  "source": "sina-a-share-spot",
  "degraded": true,
  "acquisitionComplete": false,
  "note": "东财 A 股列表不可用；新浪为在交易标的短名快照，非东财完整名单的等价候选，已拒绝交付"
}
```

`_list_stocks_em()` 保持原样；`_list_stocks()` 主源成功仍返回正常 `akshare` 候选；主源失败后可调用新浪取得诊断计数，但最终返回 `acquisitionComplete=false` 的候选或直接抛 `ProviderError`。`products` 为空即可；若为保留诊断行而带上新浪 rows，`acquisitionComplete=false` 仍会让 Web 零写入。优先选择与现有 `list_products_with_meta` 兼容、改动最小的形式；不设 `intentionalSubset=true`；新浪也失败时保留两个错误原因，不交空候选。

Web 已有首道保护，见 `web/lib/sync.ts`：

```ts
if (data.acquisitionComplete === false) {
  throw new PublishRejected(
    "incomplete acquisition candidate rejected, existing data kept",
  );
}
```

该拒绝发生在暂存表写入和正式替换之前。不采用“新旧行拼接”：无法证明代码集合完整、会混合名称和拼音口径、无法区分真实退市与备源未覆盖、难以回滚。本次选择是**完整东财候选才发布，否则整类保留旧数据**。

A 股主源失败时整轮可记 `partial_failed`，但需保留东财原始错误、新浪诊断是否到货及行数、拒绝交付原因、旧行数未变、不写 `snapshotAt`、不触发以“新列表已发布”为前提的后续动作。这比“5,580 行、看似成功但来源和口径已变化”更准确。

## 8. W3：失败类型有界自动补试

现状：`sync_scheduler.py` 明确“失败类型不自动重试”——整轮实测 9.6～13 分钟，反复重试会持续占东财源族，因此只暴露缺口，交给人或下次调度。本方案是经确认的策略变更，但只补失败类型，不重买整轮。

第一版参数：每日 02:00 自然轮失败后最多补试 **1 次**、延迟 **30 分钟**；只请求自然轮失败类型；不带 `force`，不越过 Web 当日成功幂等闸；`us` 继续走持久化任务；`inconclusive` 不补试；`running/collecting` 不补试；启动补跑、手动轮不额外繁衍补试；进程重启后从状态文件恢复未执行计划。

不复用“重跑五类”的完整 `_execute()`，拆出最小内部函数：

```text
_execute_types(trigger="daily-retry", types=[失败类型], force=False)
```

调用 `POST /api/sync?types=stock,crypto`。要求：与主任务共用同一个 `running` 单飞锁；补试期间不能并行触发另一轮同步或刷新；只合并本次涉及类型的结果，不抹去其他类型历史；成功后清除对应 pending；仍失败则当日不再自动补试；刷新腿也只覆盖本轮实际涉及类型，不能借补试重刷全市场。

复用 `sync-state.json` 增加：

```json
{
  "retry": {
    "date": "2026-11-28",
    "state": "pending",
    "attempt": 1,
    "maxAttempts": 1,
    "types": ["stock", "crypto"],
    "notBefore": "2026-11-28T02:50:00+08:00",
    "reason": "daily partial_failed"
  }
}
```

状态只允许 `pending / running / completed / exhausted / cancelled`；每次迁移原子写盘；写盘失败要显式记录，不得假装已安排。自动补试提高成功率但不保证成功，不无限重试、不增加并发、不绕开源族限速、不用人工 `POST /sync/run` 验证、不用 `force` 让成功类型重新出网。

## 9. W4：最近可用数据的状态与展示接线

现有能力应复用：分类浏览实时富集失败后回退 `Product.lastPrice`（`web/lib/browse.ts`）；分类页已有名单和价格陈旧提醒（`web/lib/freshness.ts`）；详情实时条已能保留最后价并提示（`RealtimeStrip.tsx`）；同步结果已按类型区分成功、失败、跳过、收集中；同步状态已持久化到 `sync-state.json`；Web 已支持 `?types=...`；美股已有持久化逐页续跑。

分类名单与价格：复用 `freshnessOfTypes()` 和 `staleNotes()`，但修正当前“早于昨日才提示”的宽窗口。新逻辑结合最近同步结果：今日成功正常展示；今日失败立即标历史快照，不等超过一天；尚未到调度时间不报警；周末、休市和“尚未到执行时间”不误报；展示最近成功名单日期和价格快照时间；被折叠的提醒保留总数，不能静默隐藏第三类以后。示例：

实时富集失败时继续回退 `Product.lastPrice`，明确这是快照价、不是本次实时报价，不把 `quoteSource` 留成看似实时来源；页面只需一条分型提示，不逐行重复报警。

详情实时条保留“最后价＋更新失败提示”，并强化 `isStale`：当前主要看本次轮询失败和本地成功间隔（`web/lib/realtime.ts`）；盘中还应比较上游 `price.timestamp` 与当前市场时间，防止 HTTP 200 但上游本身滞后；非交易时段不按盘中阈值误报；港股阈值可参考刚验证的 15 分钟问题，但按市场现有 `market-clock` 口径实现，不用统一 10 秒误伤所有类型。

热点按内容日期区分：当日 `engine=llm` 且非降级＝最新正常；当日 `keyword/degraded=true`＝最新但降级，继续展示并说明；当日调度失败、只能展示昨日内容＝醒目标注“当前为历史热点”；无内容＝暂无数据。当前页面已有“数据日期”（`HotspotFeed.tsx`），需结合最近调度结果判断“历史内容”，不能只靠用户自己看日期。

历史 K 线按实际交易日展示，不用实时新鲜度阈值误报历史序列；最新交易日缺失时才标缺口；本方案不新造完整交易日历，休市判断继续遵循现有市场时钟边界。

## 10. W5：热点能力恢复

配置由 compose 传入 Web 与 data-service，入口见 `docker-compose.yml` 的 `LLM_*` 透传。`llm_client.py` 的 `_cfg()` 要求 `LLM_API_KEY`、`LLM_MODEL` 非空，`LLM_BASE_URL` 非空或能按模型名推断供应商。本方案统一显式填三项，避免推断不确定性。只做一次最小 OpenAI 兼容请求验证：记录 HTTP 状态、耗时、响应是否合法 JSON；不记录 `Authorization`、完整 prompt 或密钥；不用伪造 `engine=llm` 通过验收；必须确认端点支持 `response_format={"type":"json_object"}`，否则 `chat_json` 失败、热点仍走关键词兜底。

根 `.env` 同时供 Web 和 data-service 使用，`docker-compose.yml` 已透传；不要只写 `web/.env`。`LLM_BASE_URL` 填“`/chat/completions` 之前的前缀”，代码会自行拼接；`LLM_MODEL` 填供应商控制台里的精确模型 ID；`LLM_API_KEY` 填对应密钥。

```dotenv
LLM_API_KEY=<你的 DeepSeek key>

# 智谱 GLM 示例

LLM_API_KEY=<你的 GLM key>

LLM_BASE_URL=https://<你的端点>/v1
LLM_MODEL=<端点支持的模型 ID>
LLM_API_KEY=<你的 key>
```
