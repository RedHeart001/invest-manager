# CR10-48 港股实时行情 r_ 前缀可行性试跑与最小修复方案（2026-11-25）

> **这是什么**：港股详情页价格长期滞后 15 分钟的缺陷定位、`r_hk` 实时档可行性试跑读数、最小修复方案，以及**已完成的实施与验收读数**。现值状态只认 [../FIX-LEDGER.md](../FIX-LEDGER.md)。

## 1. 缺陷

`data-service/app/providers/tencent_provider.py:119` 的 `_hk_symbol` 返回 `hk{code}`，是腾讯的**15 分钟延迟档**。港股详情页 `/api/realtime` 的现价腿由腾讯提供，因此详情页价格恒定滞后。

11-25 盘中实测（120 样本）：延迟中位 **15.1 / 15.2 分钟**；跨午休累加后可达 75 分钟。这不是停更，是档位差异。

腾讯对同一只港股提供两档符号：

| 符号 | 档位 | 盘中实测延迟 |
|---|---|---|
| `hk00700` | 15 分钟延迟 | 15.1 分钟 |
| `r_hk00700` | 实时 | 0.0 分钟 |

`r_` 前缀**不能全局套用**：对 A 股 `r_sh600519` 只返回 1 个字段（不可用），对美股 `usAAPL` 与 `r_usAAPL` 无差异。

## 3. 修复方案

### 3.1 边界

只让**详情页实时区**（`/api/realtime`）的港股现价走 `r_hk`。**其余全部不动**：

| 链路 | 符号 | 依据 |
|---|---|---|
| `/api/realtime` 港股现价 | `r_hk{code}` | 缺陷所在，同构已验证 |
| `/api/realtime` 港股分时 | `hk{code}` | `r_` 端点不支持 |
| 日 K 备源 | `hk{code}` | `r_` 端点不支持 |
| `/quote`、`/quotes`（列表富集 / 刷新） | `hk{code}` | 60 只批量虽通过，长期配额未验证 |

A 股、基金、美股完全不动。

**为什么不只改 `_quote_symbol`**：该函数被 `get_quote`／`get_quotes` 共用，改它会连带改动 `/quotes` 列表刷新，超出本方案边界。

### 3.2 改法

新增两个函数，**不改** `_hk_symbol`／`_quote_symbol`／`_symbol_for`／`fields_to_quote`：

```python
def _hk_realtime_symbol(code: str) -> str | None:
    sym = _hk_symbol(code)
    return None if sym is None else f"r_{sym}"


def _realtime_quote_symbol(type_: str, code: str) -> str | None:
    if type_ == "hk":
        return _hk_realtime_symbol(code)
    return _quote_symbol(type_, code)
```

`data-service/app/realtime.py` 的腾讯现价腿（`:234`）改调 `_realtime_quote_symbol`。

复用 `_hk_symbol` 的校验与补零，不复制规则。

### 3.3 失败处理：不静默回退

`r_hk` 返回空或失败时沿用现有 `ProviderError → degraded/stale`，**不自动改请求 `hk` 延迟档**。自动回退会把「实时档失效」伪装成一次成功，并把延迟价格重新混入。

若以后要延迟档兜底，须单独实现并显式标注「延迟行情」，不得静默替换。

### 3.4 本期不做

- **不加全局陈旧阈值**（如「报价超 20 分钟即 degraded」）：港股收盘后时间戳自然变旧，简单阈值会在闭市时误报。要做必须结合交易日历、午休与半日市，属独立增强。
- **不改列表刷新**：60 只批量通过仅证明技术可用，不证明全量 4,596 只长期刷新配额充足。
