## 二、修法与三个刻意取舍

新增 `_as_provider_error(op)`（`:158-171`，contextmanager）：`except (RequestException, ValueError) as e: raise ProviderError(f"tencent {op} failed: {type(e).__name__}: {e}") from e`。三处 `with` 只包 **I/O＋载荷提取**，字段映射（`fields_to_quote`）与 candle 构造（`minute_rows_to_candles`、日K 行循环）**留在包外**。

1. **不宽抓 `Exception`**（规格明令"不在 chain 内捕获泛化 Exception 掩盖编程错误"，本轮把同一口径守在 provider 边界）：既有套件里多处桩用 `AssertionError` 表达「不该发请求／白名单外域名」——`test_tencent_minute.py:181`、`test_cr9_symbol_guard.py:470`、`test_cr9_92_realtime.py:123`。宽抓会把它们伪装成上游失败。**诚实读数**：D2 钻证明既有那三套在宽抓下**照样全绿**（38/38、48/48、63/63）⇒ 挡住宽抓的尺**只有新套件 ⑦ 那三枚**，不是既有防线。
2. **`RequestException` 在导入期绑定**（`:18` `from requests.exceptions import RequestException`），不写 `requests.RequestException`：既有套件把本模块的 `requests` 名换成只有 `get` 的 `SimpleNamespace`／`_RequestsShim`（`test_cr9_92_realtime.py:128-130`），属性访问会 `AttributeError`。requests **2.34.2** 实测 MRO＝`JSONDecodeError → InvalidJSONError → RequestException → OSError`，且同时继承 `json.JSONDecodeError → ValueError` ⇒ 网络/HTTP/非法 JSON 三类一网打尽，`ValueError` 那条臂兜裸 json 解析。
3. **窄抓顺带免掉双层包裹**：`ProviderError`／`ProviderNotSupported` 既不是 `RequestException` 也不是 `ValueError` ⇒ 既有空载荷文案（`tencent quote empty`／`tencent kline empty: …`／`tencent minute empty: …`）与能力拒绝原样穿过，不需要 `except ProviderError: raise` 那道额外守卫（宽抓则必须加，否则包内任何 `ProviderError` 会被再包一层）。
