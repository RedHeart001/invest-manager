## 6. 副本机网络形态：两枚坑与修法

**坑一：容器 DNS 坏，但有直连出口。** 副本机宿主任意外网域名 `getaddrinfo` 失败（连 `pypi.org`、`registry.npmmirror.com` 都不行），而容器对公网 IP 可直连（实测 `223.5.5.5:53`、`1.1.1.1:443`）。首次 `docker compose build web` 因此红在 `npm ci` 的 `ENOTFOUND`，npm 只留下 `Exit handler never called!` 这层表象——**当时极易误判成依赖冲突**。修法＝gitignored 的 `docker-compose.override.yml` 给两服务指 `223.5.5.5／223.6.6.6`。不改 tracked 的 `docker-compose.yml`，真环境拉本仓库不受影响。

**坑二：自定义 `dns` 会顶掉 `host.docker.internal`。** Docker Desktop 的内建别名解析被换掉后，"境外腿经宿主代理"这条设计整体失效，而失败信息长得像上游不可用——02:00 那轮 crypto 就是死在这。修法＝同一 override 补 `extra_hosts: host.docker.internal:host-gateway`。修后复核别名解析 `192.168.65.254`、服务名 `data-service` 仍可解析、CoinGecko `/api/v3/ping` 200。**通用结论：给容器指外部 DNS 之前，必须同时把 `host.docker.internal` 用 `extra_hosts` 锁回去。**

```bash
docker compose exec -T data-service python -c "import socket;print(socket.gethostbyname('host.docker.internal'),socket.gethostbyname('data-service'))"
```
