## 背景与决策摘要

M7 优化点 1：技能触发词子串匹配（`web/lib/skills.ts` 的 `text.includes`）存在误命中。三条候选路线评估结论：

1. **TypeSafe Jev（SaaS）→ 作废**：境外托管 API（`api.typesafe.ai`）+ 新凭据/SDK 依赖，违反「白名单 + 不自动安装」；官方明示 CJK 不保证；调用点在每条消息 TTFT 的同步路径上。
2. **Laya（`github.com/NandhaKishorM/laya`，自托管）→ 未采纳留作备选**：与 Jev 同构（choice/score/noul）且本地推理、支持 zh（mmBERT-base 322M），但 Python/torch 依赖与 web（Node）侧同步调用点错配，权重 + torch 撑大 P7 镜像，成熟度未验证。
3. **路线 C → 采纳**：技能 meta 本已常驻 system prompt，注册内置工具 `load_skill(name)` 由主 LLM 自主拉取正文（"select instead of generate"），现有 LLM、零新依赖、零数据出境。

## 关键设计

- **每请求闭包而非全局单例**：加载计数随请求生灭，并发请求互相隔离（避开 C17/C27 同类坑的变种）；技能目录为空时 `def=null` 不注册。
- **失败即引导**：未知名返回可用候选列表让模型下一轮自愈；`name` 在 JSON schema `enum` + 代码侧双重白名单（C33）；正文截断复用 `maxBodyChars`（2400）。
- **回滚阀**：`SKILL_ROUTER=keyword` 一行 env 即回原行为（子串匹配代码原样保留）；`hybrid` 为中间档（关键词照注 + 工具补长尾）。
- **已知代价**：技能相关提问 +1 次 LLM 往返（决定→加载→作答）；`MAX_TOOL_ROUNDS` 维持 4（轮次耗尽有强制总结兜底）。
