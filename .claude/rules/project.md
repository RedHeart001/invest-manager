# 项目规则（Invest Manager）

> 本文件由项目根 `CLAUDE.md` 通过 `@.claude/rules/project.md` 导入，**每次会话都会加载**，不要加 `paths:` frontmatter。

## 密钥：绝对禁令

**绝不允许把主人的任何密钥 / 凭据提交进仓库。** 一旦进入 Git 历史，即使随后删除，也必须按已泄露处理。

### 本项目视为密钥的东西

| 类别 | 具体项 |
|---|---|
| LLM | `LLM_API_KEY`；`LLM_BASE_URL` 中的真实私有端点 |
| 数据源 | `TAVILY_API_KEY` / `SEARCH_API_KEY` |
| 落库回调 | `INGEST_TOKEN` |
| 基础设施 | 真实代理凭据、含口令的数据库连接串、SSH 私钥、证书 |
| 形态特征 | `sk-…`、`tvly-…`、`ghp_…`、`AKIA…`、以及赋给 `*_KEY/_SECRET/_TOKEN/_PASSWORD` 的长随机串 |

### 禁止 add 的文件（即便未被 gitignore 覆盖）

- `.env`、`.env.local`、`.env.*.local` 等真实环境变量文件。
- `*.db`、`*.db-wal`、`*.db-shm`（含真实业务数据）。
- `backups/` 下的任何文件。
- `*.pem`、`*.key`、`*.p12`、`id_rsa*`。
- `.claude/settings.local.json` 等本地配置。

> 唯一可提交的是 `.env.example` / `web/.env.example`，密钥类取值必须为空。若模板有真值，停下报告，不自行改动主人的配置。

### 提交前强制自查

```bash
git diff --cached --name-only
git diff --cached | grep -iE '(sk-|tvly-|ghp_|AKIA)[A-Za-z0-9_-]{10,}'
```

两条都干净才提交。绝不用 `git commit --no-verify` / `-n` 绕过检查。

- 尚未提交的密钥：立即撤出暂存并报告，不删除或改写 `.env`。
- 已提交的密钥：立即停下报告，不自行改写历史或 force push；提醒主人到服务方轮换凭据。

## 提交纪律

**本项目已授予常驻授权**：凡是主人让我改动了项目文件，改动完成后主动 `git add` + `git commit`，不再逐次询问。若主人在当前任务中另设提交边界，以当前指令为准。

- 只 add 本次改动涉及的具体文件；禁止 `git add -A` / `git add .` / `git add -u`。
- add 前用 `git status --porcelain` 核对，避免混入他人在制工作。
- 只读任务不触发提交；无实际变化不制造空提交。
- 使用 Conventional Commits + 中文标题；默认只写标题，必要时加不超过 5 行 body。
- **只 commit，不 push**。推送、合并、rebase、发布仍需单独授权。
- 当前在默认分支 `master` 时先问；日常开发分支是 `dev`。
- 提交失败如实报告，不改命令绕过检查。

## 项目文档结构

### 30 秒认识本项目

- 个人投资理财辅助 Agent：热点推送 / 智能搜索 / 产品详情页 / 金融分析 Agent。
- `web/`：Next.js 15 + React 19 + Prisma/SQLite，界面 + BFF，唯一对外端口和唯一写库方。
- `data-service/`：FastAPI 无业务状态取数服务，不写业务库；运行时状态与库快照均在 `.gitignore` 内。Compose 网络内不发布宿主机端口，采集结果经 HTTP 回调 web 落库。
- 行情与主数据来自 akshare、Tavily、yfinance 等，走多源降级；LLM 走 OpenAI 兼容端点。
- P0–P7 建设阶段已完成，此后进入审查期。当前轮次、下一可用编号与逐项状态现查 `docs/FIX-LEDGER.md`。

**每个事实只有一个“家”**：在原处更新，别处只留指针，不重复维护。

### 读：什么时候看哪个

| 文件 | 用途 |
|---|---|
| `docs/README.md` | 统一入口：项目是什么、文档地图、常用命令和短摘要 |
| `docs/PLAN.md` | 需求与设计唯一来源 |
| `docs/CONSTRAINTS.md` | 改代码前必查的约束、契约坑、数据源事实、部署约束 |
| `docs/FIX-LEDGER.md` | **逐项状态唯一来源**：开放/半闭/观察项、验收欠账、有效判据及已闭事项索引 |
| `docs/PROGRESS.md` | P0–P7 里程碑、当前里程碑和真实阻塞；不复制逐项状态 |
| `docs/CODE-REVIEW.md` | 当前开放轮次完整发现与误报排除表 |
| `docs/history/` | 长期价值事件档案与前向任务书，不收机械状态快照 |

### docs 结构标准（2026-11-14 修订）

1. **统一入口**：`README.md` 只留导航与短摘要；逐项状态、欠账清单、验收计数不得复制到这里。
2. **活跃工作区**：保留当前有效设计、约束、逐项状态、里程碑与发现。
3. **历史档案**：只收重要根因、关键决策、分级验收、自然窗口、事故报告与前向任务书。

具体职责：

- **PROGRESS.md**：只留 P0–P7 里程碑、当前里程碑和真实阻塞；自然观察不冒充代码阻塞。
- **FIX-LEDGER.md**：开放编号、半闭项、观察项、验收尾款、延期事项和有效判据必须保留；已闭长段可压成一行结论 + 证据链接。
- **CODE-REVIEW.md**：保留当前开放轮次完整发现；历史发现可由 Git 恢复，不为留历史重复堆进活区。
- **PLAN.md**：过时决策标注“已作废/已执行/已被推翻”；现行设计直接更新。
- **history/**：重要事件报告保留原文，不做摘要重写；普通状态变化由 Git 保存。

### 更新约定

- 状态变化只更新 `FIX-LEDGER.md`；`README.md` 与 `PROGRESS.md` 仅在导航、里程碑或真实阻塞变化时更新，不逐轮复述状态。
- 已闭事项优先留一行结论 + 证据链接；普通旧版本通过 `git log` / `git show` 查阅，**不再机械搬入 history**。
- 只有独立具备长期检索价值的事件报告或前向任务书才新建 history 文件，并更新 `history/README.md`。
- 可复算数字必须带日期 + 出处；给不出出处就写“用这条命令现查”。历史计数不得冒充现值。

### docs 体量与历史治理（2026-11-14 修订）

- 每轮收尾运行 `python scripts/docs-scan.py` 与 `python scripts/docs-scan.py --selftest`；前者检查体量与断链，断链非零必须处理。
- 活区体量报警沿用执行件现有规则；报警用于发现重复、长行和过大段落，不再自动触发“先搬 history、原地留指针”。
- **现值可直接重写**：README 短摘要、PROGRESS 里程碑/阻塞、FIX-LEDGER 当前状态、开放项与验证门槛都可原地更新，不保留逐轮“现值更正”链。
- **重写前先找活口**：开放编号、半闭项、观察项、延期事项、验收尾款和有效判据不得因压缩丢失；历史全绿不得冒充本轮实测。
- **已闭长段可压缩**为一行结论 + 证据链接；重要根因、决策、验收和事故报告不做摘要重写。
- **普通状态变化不再机械归档**：不新建“现值块归档”“状态快照”“旧行归档”，不堆“已搬归档”指针。
- **删除纪律**：只删除已跟踪、可由 Git 恢复且确认无唯一活口的机械状态快照；未跟踪文件、未提交修改、混合内容或不确定文件一律保留并报告。删除前核对引用，删除后跑断链检查。
- `--move` 仅作为确实需要保留机械原文时的可选工具；正常精简使用精确编辑，并保留用户已有改动。
- 新内容避免超长行：一段只表达一个状态或转折；表格只放短状态，详细判据放表后小节。

## 写：讨论产出的落点

| 讨论产出 | 落到哪 | 形态 |
|---|---|---|
| 新需求 / 需求变更 / 设计选型 | `docs/PLAN.md` | 需求条目或决策记录：结论 + 日期 + 理由 |
| 不得回退的约束、契约坑、数据源事实 | `docs/CONSTRAINTS.md` | 现象 + 为什么 + 正确做法 |
| 阶段/里程碑完成、真实阻塞变化 | `docs/PROGRESS.md` | 更新里程碑或阻塞，不写逐轮日志 |
| 发现问题但未定修 | `docs/CODE-REVIEW.md` | 现象 + 证据 + 复现命令 |
| 问题修复 / 决定不修 / 验证证据 | `docs/FIX-LEDGER.md` | 更新唯一状态、判据与证据 |
| 长期价值事件报告 / 前向任务书 | `docs/history/` | 日期 + 主题；任务书执行后标生命周期 |

### 落笔纪律

- 讨论过程中不动文件，结论成形后一次落笔；主人明确拍板的事项可立即落。
- 只落结论，不落聊天；探索性问答和被推翻的中间想法不写。
- 没拍板的标“待拍板”，不写成已定正文。
- 不臆测；状态须能由命令、测试或代码复现，否则标待核。
- `docs/history/` 中的重要事件报告只增不改；现值不写入归档。
- 写完按提交纪律处理；当前任务若要求另行确认，则遵循当前任务。

## 其他长期有效纪律

- 测试失败最多重试 3 次，仍失败即停止并沟通（`docs/PLAN.md` R9）。
- 开发期间不在 `next dev` 运行时执行 `npm run build`；类型检查用 `npx tsc --noEmit`。
- 修“失败负缓存 / 限流计数 / 熔断计数 / 复查窗口”类问题必须附 C34 反向验证。
- 装第三方技能必须用 `npx skills add <repo> --copy`；执行前先读 `.claude/skills/README.md`。
- 轮次计数与 Git 领先数不手写进文档，用 `git rev-list --count origin/dev..HEAD` 等命令现查。
- 关键读数不能只靠临时自动化取证；长期观察须由产生它的进程持久化落痕，排不排自动化只影响何时读取，不影响是否可读。
- 自然观察项出现即记录，不设截止、不排自动化、不为凑绿制造故障或重复购买请求。
